## Task specs

### PR431-1 — fork delta-baseline dumping [hard]

Do NOT switch forked children to a fresh profiler; the inherited instance
is what holds the already-wrapped functions.

1. Add `LineStats.__sub__`/`__isub__` in `line_profiler/line_profiler.py`,
   the exact inverse of the existing `__add__`: per-key, per-lineno
   subtraction of `(nhits, time)`, dropping entries that reach `(0, 0)`
   and raising `ValueError` on any negative result (negative means the
   subtrahend is not a prefix-baseline of the minuend). Mixed units:
   convert like `__add__` does. Symmetric doctests to the `__add__` ones.
2. In the fork wrapper's child branch
   (`cache.py::_wrap_os_fork`, child side), snapshot
   `baseline = self.profiler.get_stats()` *before* any child work, and
   pass it through `_setup_in_child_process` to `_DumpStatsHelper`.
3. `_DumpStatsHelper` dumps `prof.get_stats() - baseline` when a baseline
   is present; it must re-derive the delta on *every* dump (pool workers
   dump repeatedly).
4. Tests: (a) the P1 repro as an integration test asserting the exact
   100,001 count for `fork`, parametrized over fork/spawn/forkserver x
   Process/Pool/ProcessPoolExecutor; (b) unit tests for
   `LineStats.__sub__` incl. the negative-delta error; (c) a multi-fork
   test asserting counts don't scale with child count.

Watch out for: nested forks (falls out naturally if the snapshot happens
in every fork); the forkserver server process (baseline ~empty; harmless);
snapshot cost at fork (acceptable; document).

### PR431-2 — self-describing pool protocol [hard]

1. In `_queue.PutWrapper` with `push_to_parent=True`, wrap as
   `(_LP_PID_TAG, pid, obj)` where `_LP_PID_TAG` is a module-level unique
   string constant.
2. In `_wrap_outqueue_quick_get`: if the result is a tuple whose first
   element equals `_LP_PID_TAG`, strip and record the PID; otherwise pass
   the result through unchanged and emit a once-per-process warning
   ("worker PID unknown — child process appears unpatched; its profile
   data will be missing") via `warnings.warn` + `diagnostics.log.warning`.
3. Keep the sentinel `None` path as-is.
4. Test: patched parent + vanilla worker completes `pool.map` with correct
   results and the warning fires; guard with a hard timeout so regression
   = fast failure, not a hung CI.
5. Make silent hook failure observable: `load_pth_hook`'s
   `except Exception` branch should always `warnings.warn` (not only under
   `DEBUG`); keep the broad catch so the child still runs.

### PR431-3 — `.pth` write fallback

In `write_pth_hook`/`_setup_in_main_process`: candidate dirs in order —
the directory containing the installed `_line_profiler_hooks` module *if*
it is a site dir; `sysconfig.get_path('purelib')`;
`site.getusersitepackages()` when `site.ENABLE_USER_SITE`. First writable
wins. If all fail: `warnings.warn` with an actionable message ("cannot
install startup hook; profiling will not extend into spawn/exec children;
fork children still covered") and continue. Also: before writing, verify
`_line_profiler_hooks` will be importable by a bare interpreter using that
site dir (guards the uninstalled-checkout hazard). Tests: read-only
tempdir → warn-and-continue; fork children still profiled.

### PR431-4 — de-assert cleanup paths

`wrap_terminate_pool`: replace `assert not worker.is_alive()` with
`if worker.is_alive(): cache._debug_output(...); continue`.
`RebootForkserverPatch.reboot`: replace `assert callable(stop)` with an
explicit check that warns and skips (or raises `RuntimeError` with
context). Rationale in review P4.

### PR431-5 / PR431-6 — `_manage_profiler` robustness

`__exit__`: wrap cleanup+gather in `try/except Exception` (log + warn),
always call `_post_profile(options, prof, extra_stats_or_None)` in a
`finally` alongside `self._ctx.uninstall()`. Harden `gather_stats`:
`is_empty` treats `FileNotFoundError` as "exclude". `__enter__`: wrap the
body after `self._ctx.install()` in
`try/except BaseException: self._ctx.uninstall(); raise`.

### PR431-7 — support contract docs

Add a "Profiling child processes" docs section + `--prof-child-procs` help
epilog paragraph enumerating: supported (cooperative Python children,
normal startup, exit or flush point), best-effort (children that error but
reach cleanup), unsupported (SIGKILL, `os._exit`, hard crash, `python -S`,
cleared env, non-Python/frozen children), the pool-close caveat, and what
the empty-file warning means.

### PR431-8 — in-code registry

`Registry.get_default()` builds directly from the patch objects in
`_mandatory_patches`/`_optional_patches`/`_profiling_patches`; the
entry-point group remains as an *extension* mechanism layered on top.
Replace the `assert patch in _PATCHES` loop with a `RuntimeError` naming
the missing patch. Remove the setup.py entry-point declarations for the
built-ins (keep the group documented for third parties).
